## 一、调度器的三岔口

`trap_handler_c()` 的开头是一个关键分叉——**trap 的原因决定调度策略**:

```c
if (c->mcause == 8) {              /* 系统调用 */
    handle_syscall(c, id);
    wake_due_tasks();
    if (state[id] == RUN)
        return old;                /* ★ 同任务继续,不切换! */
}
...                                /* 非法指令等:同理跳过继续 */

/* 走到这里 = 定时器抢占 或 任务自阻塞:完整调度 */
```

那条 `return old` 是全书最值得品味的一行:**系统调用不是抢占点**。
它不是凭空设计的——v3 版本里每个 ecall 都会触发轮转,结果
`|++<0+><1><2>++<3+>` 字符级疯狂乱插队,生产者三连发被切成碎片。
事故的教训固化成原则:

> **抢占只属于定时器;系统调用只干活,不换人。**

(反例也有价值:如果你的任务想在 syscall 里"主动让出",那叫
阻塞——走 SLEEPING 状态,见第三节。)

## 二、唤醒:时间就是 wake_at

每个任务的"闹钟"存在 `wake_at[]` 里。`wake_due_tasks()` 做的事
只有一句:

```c
if (state[i] == SLEEPING && t >= wake_at[i])
    state[i] = RUN;
```

睡够的变成 RUN,等调度器挑中。**调度器从不动还没睡够的任务**——
这是它"守时"的体现,也是第 09 章 IPC 唤醒要用 `wake_at == NEVER`
区分"睡定时器"和"等信箱"的原因。

## 三、round-robin:最公平的笨办法

```c
nxt = g_cur;
for (i = 0; i <= NTASKS; i++) {
    nxt = (nxt + 1) % NTASKS;      /* 从下一个开始找 */
    if (state[nxt] == RUN) break;
}
g_cur = nxt;
rearm();                            /* 时间片重新计时 */
```

从"上一次运行者"的下一个开始扫,找到第一个 RUN 的——没人有特权,
人人每片 10000 条指令(`SLICE`)。复杂系统用优先级/多级反馈队列,
但轮转是所有调度器的零号方案:**公平,且无饥饿**。

## 四、全睡着:把空转折叠掉

两个任务都 SLEEPING 时怎么办?傻等也是等,但每秒空转几十万条指令
只为查"到点了没",太浪费。内核的选择:

```c
set_mtimecmp(w);                    /* 闹钟拨到最近一次唤醒时刻 */
return &idle_ctx;                   /* 切给 idle 任务 */
```

`idle_task()` 只有一句话:`for(;;) wfi;`。**wfi(wait for interrupt)**
在本机的实现里是"确定性休眠":把 mtime 直接快进到下一个闹钟,
下一步的中断检查自然触发——**没有意义的空转被整段折叠掉**。

真实 CPU 的 wfi 是断电降频等中断;模拟器里我们用"跳过时间"达成
同样的语义。这也是为什么 `kern_smoke` 里 2M 步能覆盖漫长的睡眠期。

## 五、kern_sleep:关中断的三步舞

任务主动睡觉,要防一个竞态:状态写到一半,定时器 trap 把你切走,
调度器看到的是半套信息。解法是经典三步:

```c
__asm__ volatile ("csrci 0x300, 8");   /* ① 关中断 */
wake_at[id] = now() + ticks;
state[id] = SLEEPING;
__asm__ volatile ("csrsi 0x300, 8");   /* ② 开中断 */
set_mtimecmp(now());                   /* ③ 立即制造 trap,马上让出 */
```

第三步也是血泪教训:v2 版本写完状态就返回了,任务继续把**剩余的
时间片**全部刷屏(`[0][1][2]` 连读事故)。标记了 SLEEPING 却还占着
CPU,等于跟调度器撒谎。**"我要睡了"和"我现在就下台"必须是
同一个动作。**

## 六、用断言锁住行为

调度器的行为怎么测试?`kern_smoke.py` 三条断言,条条对应一个设计:

| 断言 | 锁住的设计 |
|---|---|
| 消息严格递增 0,1,2,… | 邮箱不丢不重(第 09 章) |
| `+++` 存在于输出 | 环形缓冲吸收突发(否则碎成 `+<0+>`) |
| `wasd` 全部回显 | 键盘 MMIO 链路完整 |

和第 02 章的"画面变化次数"一脉相承:**行为 → 可断言的数字**。

## 本章小结

- 抢占只属于定时器;syscall/异常是"过路",不换人
- round-robin:从上一个的下一个开始找,公平且无饥饿
- 睡眠队列 + `wake_at`:调度器守时,绝不动没睡够的
- 全睡着 → idle 的 wfi:把空转折叠成时间跳跃
- kern_sleep 三步舞:关中断、写状态、立即让出——原子性与即时性缺一不可
