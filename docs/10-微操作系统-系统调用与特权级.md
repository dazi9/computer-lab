第一条命令里,任务在 U 模式执行 ecall——它没有停机,而是**掉进了内核**。
同一条指令,两种命运,取决于执行者是谁。这就是特权级。

## 一、为什么需要特权级

微操作系统 v4 之前,任务和内核同为 M 模式,任务可以:

- `csrw 0x305, 0` 把 mtvec 清零,下一次 trap 内核当场去世
- `csrw 0x304, 0` 关掉定时中断,霸占 CPU 到天荒地老
- 自己执行 ecall 停机,顺手带走另一个无辜任务

用户程序"为所欲为"不是道德问题,是**结构问题**:不区分特权级,
就没有"内核"可言。解法是把世界分两层——

```
M 模式(machine):内核。唯一能碰 CSR、能停机的层
U 模式(user):任务。ecall 是它唯一能"敲门"的方式
```

## 二、CPU 侧:mode 的进出全靠两个位

CPU 新增一个 `self.mode`(3=M, 0=U)。它只在两个地方变化:

**trap 进入内核**(`_trap_now()`):旧模式存进 `mstatus.MPP`,
`mode ← M`,顺带关中断:

```python
self.csr[0x300] = (ms & ~0x188) | ((ms & 0x8) << 4) | ((self.mode & 3) << 11)
self.mode = 3
```

**mret 离开内核**:模式从 MPP 恢复,MPP 清回 U:

```python
self.mode = (ms >> 11) & 3        # mode ← MPP
self.csr[0x300] = ... | 0x80      # MIE←MPIE,MPIE←1
```

`init_ctx()` 把新任务的 mstatus 设为 `0x80`(MPIE=1,MPP=U)——
所以第一次 mret 就把任务送进 U 模式。**MPP 是一张"回程票",
trap 时撕给你,mret 时验票放行。**

## 三、U 模式的四道禁令

进了 U 模式,以下操作全部变成 trap(mcause=2,非法指令),
内核有机会教育或终止违规者:

| 操作 | 为什么禁止 |
|---|---|
| 碰任何 CSR | mtvec/mie/mstatus 是内核的命门 |
| wfi | 睡眠是内核提供的服(sys_sleep),不能自己睡 |
| mret | 伪造回程票 = 越狱 |
| ebreak | 断点属调试器,归内核管 |

而 **ecall 获得了新身份**——这是本章的题眼:

```python
elif inst == 0x00000073:          # ecall
    if self.mode == 0:            # U 模式:系统调用 → trap(8)
        self._trap_now(8, mtvec); return
    self.halted = True            # M 模式:停机(独立程序兼容保留)
```

**同一条指令,M 模式里是"关机键",U 模式里是"门铃"。**
指令不变,身份由特权级决定。

## 四、内核侧:系统调用表

trap_handler_c 看到 mcause=8,交给 `handle_syscall(c, id)`:

```c
unsigned n  = c->r[16];           /* a7 = 调用号 */
unsigned a0 = c->r[9];            /* a0 = 第一个参数 */
switch (n) { 1: putc · 2: putdec · 3: sleep · 4: send
            · 5: recv · 6: gettime · 0: halt }
```

每个分支末尾都有一个 `c->mepc += 4`——**推进 mepc 跳过 ecall**,
返回后任务从下一条指令继续。这个细节承载两种语义:

- **推进**:调用完成(如 putc/成功 send)
- **不推进**:调用没完成(邮箱满/空,任务被标记 SLEEPING)——
  醒来后**重试同一条 ecall**(第 09 章的阻塞语义在此收口)

## 五、SYS_HALT:让 CPU 自己走进停机室

任务想关机,但 U 模式的 ecall 只是门铃。内核不能替它按下停机键?
能,但要借道:`halt_stub` 是 kern.S 里一段 M 模式的 `ecall`。

```c
c->mepc    = (unsigned)&halt_stub;      /* mepc 指向停机室 */
c->mstatus |= 0x1800;                   /* MPP=M:回程票改成 M 模式 */
return c;                               /* 立刻调度它 */
```

mret 后 CPU 处于 M 模式、PC 指向 halt_stub 的 ecall——**CPU 自己
走进了停机室**。内核全程没有"关机"的权限,它只是安排了一次
合法的经过。这个"改写回程票"的模式,就是真实 OS 里信号处理、
sigreturn 的缩影。

## 六、原则的最终章

第 08 章说过"syscall 不是抢占点"。本章补全它的边界:唯一的例外是
**阻塞式 syscall**(邮箱满/空)——任务把自己标记 SLEEPING,这是
**主动下台**,与被抢占是两回事。

| 事件 | 换人吗 | 为什么 |
|---|---|---|
| 定时器中断 | ✅ 抢占 | 公平性所系 |
| 任务阻塞 | ✅ 让贤 | 它自己说了"我等" |
| 普通syscall | ❌ | 干活的人不被打扰 |

## 本章小结

- M/U 两层:trap 进内核(MPP 撕票),mret 回用户(验票放行)
- U 模式四道禁令;ecall 身份由特权级决定:门铃 or 关机键
- syscall 表 + mepc 推进/不推进 = 完成与重试两种语义
- SYS_HALT:不越权,而是"安排一次合法经过"
- 内核卷(07~10)到此收官
