## 一、框架总览:三层递进

调试大型系统的痛点是:现象在应用层,根因可能在任何一层。三层法
就是**从便宜到昂贵**逐层下钻:

```
第一层 行为断言   把现象变成可比较的数字/模式     (成本:零)
第二层 数据监视   让可疑数据自己招供             (成本:插桩代码)
第三层 真相审判   用地基(汇编/符号)审判上层     (成本:读二进制)
```

每层都可能直接破案;破不了,带着第一层的结论下到第二层。

## 二、第一层:行为断言

把"看起来不对"翻译成**可比较的数字或模式**。本项目三个真实案例:

| 现象 | 断言化 | 结论 |
|---|---|---|
| 内核输出 `\|++<0+><1><2>` | 统计 `+` 的分布 | syscall 在轮转任务 → syscall 不该是抢占点 |
| 时钟输出 `[0][1][2]` 连读 | 检查两次打印的间隔 | kern_sleep 没有立即让出 |
| 快照不变化 | `moves >= 10` | 球没动/没画 |

第一层的威力在于**把调试问题缩小成"哪个数字不对"**,而且断言一旦
写好,就永久留在测试里防回归——调试的副产品是测试资产。

## 三、第二层:数据监视——让数据自己招供

第一层告诉你"sp 槽位的值不对",第二层回答"**是谁写的**"。方法:
子类化 CPU,拦截可疑地址的写入,记录肇事 PC:

```python
class Dbg(RV32):
    def write(self, addr, val, size):
        if (addr & 0xFFFFFFFF) == 0x80000EA4:   # 可疑地址
            self.log.append((self.pc, val))
        super().write(addr, val, size)
```

真实战果:内核 sp 槽位案——监视点抓到"pc=0x240 反复写入 ctx 指针",
配合"IN_READY 寄存器总共只被读过 3 次"的读取计数,两条证据直接
锁定事故现场。**让数据自己招供,比人脑推演快一个数量级。**

同族工具:`tools/net_probe.py`(连通探针)、给 `read()` 加计数
(输入设备"为什么没人读"就是这么破的)。

## 四、第三层:真相审判——用地基审判上层

监视点给了 PC,最后一步:这个 PC 到底在执行什么?三个审判工具:

1. **用 CPU 自己的 `decode()` 反汇编**:把嫌疑指令翻译回来——
   当年 0x240 处的 `FFDFF06F` 被译成 `jal x0, -4`(自跳转),
   一眼认出那是 idle 任务的循环,排除了一个嫌疑人
2. **ELF 符号表**:`tools/elf_sections.py` 解析节表,确认
   0x80000000 处到底排了什么(抓出 .eh_frame 孤儿节事故)
3. **手算对照**:把指令按规范逐位拆开,和文档比对——CHIP-8 译码
   bug、mstatus 位洗牌错误都是这么铁证如山的

## 五、八大坑复盘表(现象 / 定位层 / 根因 / 教训)

| # | 坑 | 定位层 | 根因 | 教训 |
|---|---|---|---|---|
| 1 | 6XNN 指令无效 | 一(单元测试) | 用寄存器下标当指令族分发 | 先写规范编码基准再写实现 |
| 2 | la 汇编报错 | 一(编译期) | `dict.get(k, parse_int(k))` 急切求值 | 默认参数不是懒求值 |
| 3 | 中断永不触发 | 一(timer 测试) | CSR 字典整数键/字符串键混用 | 键类型要单一 |
| 4 | 只有第一次中断 | 二(逐步追踪) | mstatus 洗牌方向反 + 漏 MPIE←1 | 位操作画图再动手 |
| 5 | 定时器永不到点 | 二(值检查) | CLINT 复位值全 F,半字写保留高位 | 复位值抄真实硬件 |
| 6 | 开机执行垃圾 | 三(ELF 节表) | 孤儿节 .eh_frame 排到 .text 前 | 裸机必须 /DISCARD/ |
| 7 | 任务栈形同虚设 | 二(监视点)+ 三(反汇编) | 交换后 x2 已是 ctx 指针 | 交换类技巧问"数据在哪一份" |
| 8 | syscall 乱插队 | 一(输出模式) | 每次 ecall 都轮转任务 | 区分抢占点与过路点 |

## 六、通用心法

1. **先固化,再动手**:改任何东西之前,把现象变成断言
2. **二分隔离**:deci.c 无内核实验,一步切掉一半嫌疑
3. **测试全绿 ≠ 没有潜伏 bug**,只说明"还没踩到"——sp bug 全绿
   藏了两轮
4. **最小复现**:能把 bug 缩成 20 行,就缩;缩不动的复现是
   没找到真正的边界
5. **信任链**:手算基准 → 能跑 → 字节对照(第 03 章),对新组件
   逐层建立信任,而不是一次相信一坨

## 本章小结

- 三层递进:行为断言(零成本)→ 数据监视(插桩)→ 真相审判(地基)
- 每层都有真实战果;层与层之间用"结论"传递
- 复盘表是最快的成长方式:每个 bug 都值得留下四行记录
