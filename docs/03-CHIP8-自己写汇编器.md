# 03 · CHIP-8:自己写汇编器

> 这一章你会学到:机器码和汇编语言的关系;汇编器为什么必须"两遍扫描";
> 标签是怎么变成跳转地址的;以及怎么建立对一段编译产物 ms-level 的信任。
> 配套源码:`chip8/chip8/asm.py`(约 150 行)

## 先跑起来

```bash
cd ~/computer-lab/chip8
python3 roms/make_roms.py                 # 把 BOUNCE_SRC 汇编成 roms/bounce.ch8
od -A x -t x1 roms/bounce.ch8 | head -3   # 亲眼看看机器码长什么样
python3 tests/test_cpu.py | tail -1       # 15/15,信任链的最后一环
```

`od` 打出来的第一行里有 `60 08 61 04`——第一章解剖过的 `6XNN`!
这就是汇编器吐出的机器码,和源码一行行对应。

## 一、为什么需要汇编器

第一章我们解剖过 `0x6012`(V0 ← 0x12)。但让人直接写:

```
60 08 61 04 A2 1E D0 16 66 04 F6 15 ...
```

写三行就错、十行就疯。于是发明**汇编语言**——助记符 + 寄存器名 +
标签,由一个"查表 + 数数"的翻译程序变成机器码。这个翻译程序
小得惊人:`asm.py` 一百来行,核心只有两个函数。

## 二、为什么是"两遍"扫描:前向引用问题

看这个程序:

```asm
loop:   DRW V0, V1, 6      ; 用了 loop 的地址……
        JP  loop           ; 可 loop 自己在第一行,还没扫到!
```

`JP loop` 要填入 loop 的**字节地址**,但汇编器从上往下读,读到这句时
还不知道 loop 在哪。解法:扫两遍——

```
第一遍 parse_items():切条目、数大小、记标签地址
   ├── 每条指令固定 2 字节,DB 数据按字节数
   └── 标签表:loop → 0x200, ball → 0x21E …
第二遍 encode_ins():逐条编码,标签查表换成地址
```

`assemble()` 就是这两遍的骨架。所有汇编器(包括第 05 章 RISC-V 的
`rv/asm.py`)都长这样,区别只是语法多花哨、表多大。

## 三、编码:查表 + 拼装

`encode_ins()` 处理一行,比如 `DRW V0, V1, 6`:

```
D = 绘图族(高 4 位)  →  0xD0
V0 → 寄存器字段 x      →  | 0x0
V1 → 寄存器字段 y      →  | 0x1 << 4
6  → 精灵行数 n        →  | 0x6
拼装结果               =  0xD016
```

`vreg()` 把 `V3` 翻成 3,`_imm()` 检查立即数范围——**在汇编期就报错**,
比运行期才发现好一万倍。这就是汇编器给你的第一层保护。

## 四、数据与"人话":DB 和注释

精灵图案(小球的长相)是纯数据,用 `DB` 直接塞进程序:

```asm
ball:   DB  0x3C, 0x7E, 0xFF, 0xFF, 0x7E, 0x3C
```

`draw` 指令用它时,I 寄存器指到 `ball` 标签即可——**数据也住地址空间**,
代码和数据的界限只在"PC 会不会走到这里"。`BOUNCE_SRC` 全文读下来
就是一篇人能读懂的程序:第一章学过的取指-执行,在这里被"写"了出来。

## 五、信任链:凭什么相信汇编器没写错

教学项目最宝贵的一课:**信任要分层建立**。本项目对汇编器的验证有三层:

1. **手算基准**:`tests/test_cpu.py` 用第一章手算的规范编码
   (如 `0x6012`)锁死汇编器输出,谁改坏了立刻红
2. **能跑**:汇编出的 ROM 在模拟器上真的画得出小球(`tests/smoke.py`)
3. **字节对照**:`od` 打印二进制,肉眼与手算比对

以后你见到任何编译器、序列化器、压缩器,都可以套用这条
"**基准 → 能跑 → 对照**"的信任链。

## 本章小结

- 汇编器 = 两遍扫描:第一遍定位(标签表),第二遍编码
- 前向引用是"两遍"存在的唯一理由
- DB 让数据住进地址空间;标签让代码和数据互相找到
- 信任链:手算基准 → 能跑 → 字节对照
