# 02 · CHIP-8:屏幕、键盘与声音

> 这一章你会学到:位图怎么"画"进终端(ANSI 转义与半块字符);
> 键盘事件怎么被一个死循环读到(termios + 轮询);以及无头测试的思想——
> 把"看起来在动"变成一条可断言的数字。
> 配套源码:`chip8/chip8/emu.py`(约 150 行)

## 先跑起来

```bash
cd ~/computer-lab/chip8
python3 -m chip8.emu roms/paddle.ch8     # 挡板:按 1 / 4 移动,ESC 退出
```

第一章的 CPU 只会"算",这一章解决三件事:画面从哪来、按键从哪进、
声音怎么响。这三个问题在真实的电脑上分别叫:显卡、键盘控制器、声卡。

## 一、屏幕:一个字节 = 一个像素

CPU 的 `self.display` 是一块 64×32=2048 字节的位图,1 = 亮。
问题:怎么把它画到终端上?终端没有"像素",只有字符格。

`half_block_frame()`(riscv 版在 `rv/emu.py`,同款思路)的答案分两步:

**第一步:选字符**。Unicode 半块字符 `▀ ▄ █` 上半、下半可以独立着色,
等于**一个字符格塞两个像素**——64×32 的屏压成 16 行文本,宽高比
从 1:8 修正到 1:4,不再瘦长:

```
像素两行        字符一行
 ██ ██          ▀▀ ▀▀
 ██ ██          ██ ██
```

**第二步:只移动光标,不整屏重画**。每帧输出
`\x1b[H`(光标回原点)+ 新画面,终端自己覆盖上一帧。整个"显卡"
就是十几行字符串拼接。

顺带认识三个常用的 ANSI 转义:
`\x1b[?1049h/l` 进入/退出备用屏(退出后恢复你的命令行)、
`\x1b[?25l/h` 隐藏/显示光标、`\x1b[J` 清除光标以下内容。

## 二、键盘:从死循环里偷按键

交互程序的经典矛盾:CPU 在死循环里跑游戏,谁来读键盘?
CHIP-8 的答案(也是几乎所有游戏的答案):**每帧开头轮询一次**。

`run_interactive()` 每帧做三件事:

```python
while select.select([sys.stdin], [], [], 0)[0]:   # 有按键吗?(非阻塞)
    ch = sys.stdin.read(1)                        # 读一个键
    cpu.keys[KEYMAP[ch]] = True                   # 按下,写进"键盘控制器"
...
for _ in range(8): cpu.step()                     # 跑 8 条指令
cpu.tick()                                        # 定时器走 1 格
```

三个细节值得咂摸:

1. **键位映射**:PC 的 `1234/qwer/...` 对应 CHIP-8 的
   `123C/456D/...`(`KEYMAP` 表)——真实键盘控制器也是把物理键
   翻译成"扫描码",一层映射而已
2. **没有 keyup**:终端只报告"按下",不报告"松开"。于是用最朴素的
   workaround:按下时记一个 150ms 后的过期时间,主循环每帧检查,
   到点自动松开(`keys_down` 字典)。能用,但玩长按类游戏会露馅——
   这是终端作为"游戏机"的先天限制,也是很好的权衡案例
3. **按键去哪了**:`cpu.keys[...] = True` 就是写进了"键盘控制器"。
   对程序来说,它读 `EX9E` 指令时查的就是这块状态——外设即内存,
   这句话第 06 章会正式展开

## 三、无头模式:把"看起来在动"变成断言

图形程序最难的测试问题是:画面对不对,谁来判?`run_frames()` +
`ascii_frame()` 给出教科书式答案——**把帧转成文本,断言文本变化**:

```python
snaps = run_frames(cpu, 120)                       # 每帧存一张 ASCII 快照
assert any('#' in s for s in snaps)                # 屏幕亮过
moves = sum(1 for a, b in zip(snaps, snaps[1:]) if a != b)
assert moves >= 10                                 # 画面真的在动
```

这就是 `tests/smoke.py` 的全部思想:**不许人眼参与,行为变成数字**。
后面 RISC-V 内核的冒烟测试(断言 UART 流里 A/B 交替、消息严格递增)
用的是同一招,只是文本换成了消息流。

## 四、声音:一行代码的极简主义

`ST` 定时器 > 0 时,主循环每帧输出一个 `\a`——终端响铃。整个"声卡"
一行。1977 年的 CHIP-8 也就一个蜂鸣器:音效系统的本质是
"什么时候响、响多久",音色是锦上添花。

## 本章小结

- 位图 → 终端:半块字符压缩高宽比 + ANSI 光标控制 = 十几行的"显卡"
- 交互循环:每帧轮询键盘 → 写按键状态 → 跑 N 条指令 → tick 定时器
- 终端没有 keyup:150ms 自动松开是有意识的权衡
- 无头快照测试:把视觉行为翻译成可断言的数字,人眼退出测试流程
